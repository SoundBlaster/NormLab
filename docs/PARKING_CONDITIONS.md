# Парковочный пилот: таблица условий

Дата: 2026-10-04. Основание: [реестр источников](PARKING_SOURCES.md). Статус: design draft для corpus и review; исполняемые правила ещё не утверждены.

Таблица разделяет юридические условия, входные утверждения и ограничения прототипа. IDs — предложенные имена для дальнейшего контракта. Положительное значение появляется только после review. `unknown` не равно `false`; конфликт хранится отдельно и блокирует затронутый вывод.

## Базовый рассчитываемый сценарий

Один эпизод на обычной городской парковке Москвы в подтверждённый платный период, физическое лицо и личный автомобиль. Два варианта: оплаты нет либо успешная своевременная оплата правильного автомобиля/зоны покрывает весь интервал размещения. Особые обстоятельства и льготы должны быть рассмотрены явно.

## Выявляемые зависимости без отдельной модели

| ID                          | Обстоятельство                                                                    | Поведение пилота                                                     |
| --------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| C08 `attribution`           | Автоматическая фиксация, спор собственника/водителя                               | Сохранить роли; не назначать персональную ответственность без модели |
| C14 `disability_conditions` | Инвалидность, перевозка, специальное место                                        | Выявить потенциальную льготу/иной состав; unsupported                |
| C15 `special_tariff`        | Социальный, перехватывающий, динамический тариф, нулевая ставка, связанные сессии | Unsupported; нулевая ставка не означает отсутствие обязанностей      |
| C16 `fault_and_exclusions`  | Сбой приложения, вынужденная остановка, вина, возраст и другие исключения         | Выявить ограничения; не выдавать безусловный вывод о полном составе  |

Исправления сессии, ошибки номера автомобиля/зоны, поздняя оплата и спорное продление сохраняются как исходные утверждения, но их правовые последствия не вычисляются. Пользователь видит: «Этот случай пока не поддерживается; окончательный вывод о нарушении не рассчитан».

## Предлагаемая последовательность решения

1. Проверить границы сценария и нормативного пакета: эпизод, территория, вид парковки, субъект и дата.
2. Установить наличие обязанности оплаты с учётом режима и применимых исключений.
3. Проверить C12 и остальные границы. При особом случае остановить базовый расчёт с `unsupported`; при неизвестности запросить уточнение. В базовом scope рассмотреть отсутствие оплаты либо своевременный корректный платёж с покрытием всего интервала. Полную модель исправлений не реализовывать.
4. Отдельно проверить основания отнесения события к субъекту и материальные условия ответственности.
5. Вычислить последствия в поддержанном scope; затем сверить исходное утверждение о санкции.

Это инженерная декомпозиция, а не утверждение, что эти пять шагов исчерпывают действующее право. Нельзя реализовать `paid_zone && !paid => guilty`. До закрытия C08/C16 допускается только вывод о проверенных условиях обязанности/неуплаты с явной границей, а не надпись «состав доказан».

## Типы выводов для будущего UI

| Вывод                                     | Значение                                                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Условия поддержанного фрагмента выполнены | Все включённые predicates установлены; показываются assumptions и границы проверки ответственности        |
| Условие выбранного фрагмента опровергнуто | Назван конкретный predicate; это не означает отсутствия любых иных нарушений                              |
| Требуется уточнение                       | Существенный вход неизвестен; показать вопрос и возможные исходы                                          |
| Противоречие                              | Есть несовместимые reviewed assertions; показать источники, не выбирать скрытно                           |
| Не поддержано                             | Не хватает семантики или нормативной зависимости; пользовательское подтверждение не устраняет этот пробел |
| Условный результат                        | Расчёт на явно гипотетической предпосылке; не меняет факты основного эпизода                              |

Числовой baseline санкции для граждан в S01 — 5 000 рублей. Его использование требует lock применимой редакции и остальных условий. Не подставлять сумму в `inconclusive` как уже назначенное наказание.
