# R3: события, интерпретации и атрибуция

Дата: 2026-10-25. Ledger: [#225](https://github.com/SoundBlaster/NormLab/issues/225).
Код: [общие события](../lean/EventTransitions.lean),
[человеческая атрибуция](../lean/ActionAttribution.lean).
Общая модель: [RELATIONAL_FOUNDATIONS](RELATIONAL_FOUNDATIONS.md).

## Три разных слоя

| Слой                           | Содержание                          | Что установлено                                                       |
| ------------------------------ | ----------------------------------- | --------------------------------------------------------------------- |
| Событие и изменение состояния  | EventKey, before/after, точный diff | Записанные наблюдения и их различие                                   |
| Интерпретация                  | RoleView и причинные гипотезы       | Выбранное описание ролей и связей; не автоматическая причинная истина |
| Атрибуция и нормативная оценка | Отдельные профили и решения         | Только выводы по явно заданным основаниям/правилам                    |

Актор — роль любой Entity: человека, сообщества, природного явления, AI-агента
или машины. Сознание, намерение и управляемость не встроены в определение роли.
Одна сущность может быть объектом одного события и актором другого.

## Общий Context без обязательного человека

`NormLabEvents.Universe` содержит только Entity, Episode и Action; классификация
людей в нём не требуется. `Context` объединяет:

- `EventKey`: eventId, эпизод, вид описанного события и границы интервала;
- `RoleView`: interpretationId, actor, target и необязательный instrument.

`RecordedTransition` хранит Context и заданные состояния `FiniteState Fact`.
Он требует корректный порядок границ, вычисляет точные Added/Removed и доказывает
roundtrip. Тип Fact выбирает предметная модель; примеры используют небольшие
типизированные факты о крыше, документе и положении машины.

Это запись наблюдаемого перехода, **не checker физической причинности**.
Произвольные before/after не становятся установленной причиной только из-за
наличия записи. К общей записи не прикрепляется вымышленный humanAnchor.

### Интерпретация не переписывает наблюдения

`reinterpret(transition, roleView)` меняет только ролевую интерпретацию.
Доказаны сохранение EventKey, обоих состояний и consequence. Другой eventId,
эпизод, вид события или границы не могут быть выданы этой операцией за тот же
EventKey. Идентификаторы интерпретаций предоставляет вызывающий код; глобальный
реестр уникальности версий этим срезом не реализуется.

При ином масштабе описания могут понадобиться другие EventKey и другие границы
состояний. Например, предполагаемое «человек не зафиксировал машину» и
«машина скатилась» — отдельные события, соединяемые причинной гипотезой.
`CausalHypothesis` хранит ссылки и interpretationId. Это утверждаемая гипотеза:
из неё не выводятся автоматически достоверность связи или ответственность.

## HumanContext — отдельный профиль

`NormLabActionAttribution.Universe` расширяет общую Universe предикатом IsHuman.
Только `HumanContext` расширяет общий Context полем `humanAnchor : Human`.
`humanCandidate` добавляет участника к выбранному Context, сохраняя его EventKey
и RoleView; это кандидат, а не успешная проверка или вменение ответственности.

HumanAnchor — человеческий вклад в рассматриваемую цепочку. Actor остаётся
самостоятельной Entity, в том числе абстрактным сообществом. Для AI-файловой
операции не требуется автоматически объявлять запускавшего агента человека
исполнителем этой операции: запуск можно описать отдельным событием, а связь
исследовать отдельно.

Все literals человеческого профиля содержат полный контекст, включая eventId,
interpretationId и humanAnchor. Общие identity proofs и witnesses отклоняют
подмену события/интерпретации наряду с подменой участников и интервала.

### Два проверяемых человеческих профиля

```text
Действие:
  attributed(ctx)+, performed(ctx)+
    → actionGrounded(ctx)+
    → предложение добавить relationActive(ctx)+

Бездействие:
  attributed(ctx)+, required(ctx)+, deadlineElapsed(ctx)+,
  capable(ctx)+, exception(ctx)-, performed(ctx)-
    → omissionGrounded(ctx)+
    → предложение добавить breachRecorded(ctx)+
```

Attribution — явно принятое основание отнесения человеческого вклада к actor.
Членство в сообществе или наличие собственности сами по себе его не задают.
`performed` описывает выбранный человеческий вклад в этом контексте.
`deadlineElapsed` — установленное входное обстоятельство, а не календарный парсер.

Каждая выбранная предпосылка должна иметь требуемую поддержку без противоположной.
Unknown и конфликт не становятся определённым нарушением; посторонние конфликты
сохраняются. Каталог должен содержать правило профиля. Канонический R2b certificate
использует все его посылки, поэтому candidate как исходный факт и постороннее
правило не обходят проверку.

`propose` возвращает `Option GroundedTransition`. Для принятого значения after,
certificate и consequence вычисляются из проверенного входа:

```text
before = ofList(facts)
after = before ∪ { effect(kind, humanContext) }
consequence = diff(before, after)
```

Append-only ограничения относятся к этим двум человеческим профилям. **Общие
события допускают и удаления**, например «крыша цела» → «крыша повреждена».
`added_has_grounds` связывает каждый новый факт человеческого профиля с тем же
контекстом, явной атрибуцией и checked derivation; frame и roundtrip сохранены.
Derived candidate не продвигается автоматически в базовое состояние.

## Примеры и границы доказанного

| Пример                                                  | Ожидаемое и доказанное                                                           |
| ------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Ураган повредил дом                                     | Непустые Removed/Added без человеческого профиля                                 |
| AI-агент изменил документ                               | Замена версии A на B без обязательного человека                                  |
| Машина скатилась на место                               | Замена положения дороги на парковочное место                                     |
| Машина — актор в одном view, инструмент в другом        | Наблюдения и diff прежние; новая роль не устанавливает ответственность владельца |
| Предполагаемое предыдущее бездействие                   | Отдельный EventKey, не замаскированная смена ролей того же события               |
| Модель с пустым HumanContext                            | Общее событие всё равно представимо                                              |
| Человек, сообщество с явной атрибуцией, self-action     | Человеческий checker принимает полные основания                                  |
| Подмена eventId или interpretationId                    | Человеческий checker отклоняет её даже с правилом подменённого контекста         |
| Unknown, противоположная поддержка, недостающие условия | Прежние строгие проверки человеческого профиля сохранены                         |

Только выбранная интерпретация и принятые правила определяют смысл вычисляемого
вывода. Нормативное вменение ответственности, многошаговый поиск причин,
provenance физических источников и санкции остаются отдельными расширениями.

## Проверки

Lean 4.30.0, `-DwarningAsError=true`. Event gate требует 12 named results и
проверяет 237 declarations / 60 theorem declarations. Обновлённый attribution
gate требует 45 named results и проверяет 367 declarations / 132 theorem declarations.
Проверяются private/generated определения; allowlist `[propext, Quot.sound]`,
без custom axioms, `sorryAx`, `Classical.choice` и native-decide trust extension.

[Команды воспроизведения](RELATIONAL_FOUNDATIONS.md#воспроизведение) и CI
компилируют пять модулей и запускают пять gates. Локальные outputs/logs находятся
на проверенном TB5. Hosted CI/review учитываются отдельно по новому SHA;
результаты прежней ревизии PR не подтверждают эту. Runtime suites локально,
платные вызовы и деплой не выполнялись; demo пока использует прежний evaluator.
