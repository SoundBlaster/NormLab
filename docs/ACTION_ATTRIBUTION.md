# R3: события, интерпретации и атрибуция

Дата: 2026-10-25. Ledger: [#225](https://github.com/SoundBlaster/NormLab/issues/225).
Код: [общие события](../lean/EventTransitions.lean),
[человеческая атрибуция](../lean/ActionAttribution.lean).
Общая модель: [RELATIONAL_FOUNDATIONS](RELATIONAL_FOUNDATIONS.md).

## Три слоя

| Слой                   | Представление                                       | Контракт                                                                                                       |
| ---------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Наблюдения             | RecordedEvent + EventRegistry                       | Запись содержит key, before/after и корректный интервал; один ID соответствует одной записи в выбранном снимке |
| Интерпретация          | Interpretation event + CausalHypothesis             | Роли ссылаются на запись; гипотеза связывает зарегистрированные события и их интерпретации                     |
| Человеческая атрибуция | HumanContext registry + GroundedTransition registry | Профиль проверяет основания для конкретной записи и создаёт вычисляемую логическую аннотацию                   |

Актор — роль любой Entity: человека, сообщества, природного явления, AI-агента
или машины. Сознание, намерение и управляемость не встроены в определение роли.
Одна сущность может быть объектом одного события и актором другого.
Общая Universe содержит только Entity, Episode и Action; человеческая
классификация требуется только отдельному профилю атрибуции.

## Запись события и её идентичность

`RecordedEvent` хранит EventKey, состояния `FiniteState Fact` и доказательство
`start ≤ finish`. Он вычисляет точные Added/Removed и удовлетворяет roundtrip.
Ролевых полей в записи нет. Тип Fact выбирает предметная модель.

`EventRegistry.lookup : Nat → Option RecordedEvent` задаёт один неизменяемый
снимок реестра. `key_matches` связывает индекс lookup с eventId записи.
`RegisteredEvent registry` содержит запись и доказательство её присутствия.
Доказано: одинаковый eventId у двух зарегистрированных записей этого снимка
означает равенство самих записей, ключей и наблюдений. Перезаписать состояния
или action/интервал под занятым ID и сохранить RegisteredEvent невозможно.

Это модель снимка, а не реализованный persistent store или глобальный сервис ID.
Разные свидетельства об одном происшествии могут сохраняться как разные записи;
уточнение наблюдений требует отдельного ID либо явно другого снимка. Уникальность
между разными снимками и их синхронизация этим срезом не доказываются.

Наблюдения заданы входом; наличие записи не доказывает истинность фабулы или
физическую причинность. Противоречащие свидетельства не удаляются автоматически.

## Интерпретация не приносит собственных состояний

`Interpretation event` содержит только RoleView: interpretationId, actor, target
и необязательный instrument. Состояния и consequence доступны только из
индексирующей записи event. Для любых двух интерпретаций одной записи доказано
равенство before/after и consequence. Гарантия относится ко всем значениям этого
типа, а не только к отдельной функции смены ролей.

`Context = EventKey + RoleView` остаётся сериализуемым описанием scope.
Сам по себе Context не является записанным событием. Числа interpretationId
не имеют глобального реестра уникальности; проверяемые связи хранят сами
интерпретации, привязанные к записям, а не только их числовые метки.

## Причинная гипотеза

`CausalHypothesis cause consequence` связывает два RegisteredEvent одного
снимка, содержит их Interpretation и требует:

- разные eventId;
- `cause.start ≤ consequence.start`;
- корректные интервалы обоих концов, унаследованные от RecordedEvent.

Это временной профиль пилота, не универсальная теория причинности.
Перекрытие интервалов допускается: «не зафиксировал машину» может длиться
одновременно с началом скатывания. Self-link и причина, начинающаяся позже
следствия, исключены. Эти ограничения проверяют форму гипотезы;
они не устанавливают её физическую истинность, ацикличность всей сети или
нормативную ответственность. Необработанные внешние гипотезы с неверными полями
не могут быть приняты как значения этого типа без выполнения контракта.

## HumanContext и проверяемый результат

`NormLabActionAttribution.Universe` добавляет IsHuman.
`HumanContext registry` содержит RegisteredEvent, его Interpretation и
`humanAnchor : Human`. `humanCandidate(event, view, anchor)` создаёт такой
кандидат. Произвольный Context или незарегистрированный номер передать вместо
записи нельзя; кандидат сам по себе ещё не является успешной проверкой.

Низкоуровневые `Profile.Scope`, `Profile.check` и `Profile.UnboundTransition`
проверяют только переданные логические основания. Они намеренно отделены от
публичных `check`, `propose` и `GroundedTransition registry`, которым требуется
HumanContext с доказанной регистрацией. Формирование согласованных фактов для
придуманного scope не создаёт запись реестра и не обходит публичную привязку.

Literals профиля содержат полный scope: участников, instrument, эпизод, action,
интервал, eventId и interpretationId. Scope публичного HumanContext вычисляется
из записи и её интерпретации; его key нельзя заменить независимым полем.

### Два человеческих профиля

```text
Действие:
  attributed(ctx)+, performed(ctx)+
    → actionGrounded(ctx)+
    → предложение добавить relationActive(ctx)+

Бездействие:
  attributed(ctx)+, required(ctx)+, deadlineElapsed(ctx)+,
  capable(ctx)+, exception(ctx)-, performed(ctx)-
    → omissionGrounded(ctx)+
    → предложение добавить breachRecorded(ctx)+
```

Attribution — явно принятое основание отнесения человеческого вклада к actor.
Собственность или запуск AI-агента сами по себе этого основания не дают.
`performed` описывает выбранный человеческий вклад; `deadlineElapsed` — заданное
обстоятельство, а не календарный парсер. Каждая предпосылка требует поддержки
без противоположной. Unknown, конфликт, отсутствующая посылка или отсутствие
правила в каталоге не дают определённого результата. Канонический R2b certificate
проверяет все посылки; candidate-факт и постороннее правило не обходят проверку.

`propose` возвращает `Option GroundedTransition registry`. Его вычисляемые
before/after — **состояния логических оснований и аннотаций**, а не замена
наблюдений RecordedEvent:

```text
before = ofList(facts)
after = before ∪ { effect(kind, context.scope) }
consequence = diff(before, after)
```

Доказаны provenance, roundtrip и привязка каждого нового literal к key
зарегистрированного события. В частности, breach для другого key не появляется
в Added. Существующие посторонние факты и конфликты сохраняются.
Append-only относится к этим профилям; физические наблюдения общих событий
могут содержать удаления и добавления.

## Сквозной пример машины

В одной Universe и одном реестре зарегистрированы два события:

1. `unsecured`: владелец не зафиксировал машину, интервал [0,5]. До и после
   присутствует carUnsecured. Нулевой физический diff допустим: бездействие не
   обязано менять наблюдаемую проекцию состояния.
2. `car`: машина переместилась с дороги на место, интервал [4,5]. Старое положение
   удалено, новое добавлено. Машина — актор; альтернативный ownerView является
   только кандидатом интерпретации ролей.

`CarWitness.context` привязан к записи unsecured и роли owner. При явно заданных
attributed/required/deadlineElapsed/capable/exception-/performed- omission-checker
принимает предложение. `proposedCause` связывает unsecured и car с их
интерпретациями; интервалы перекрываются. Физическая достоверность этой связи
не выводится из принятия omission-профиля.

`CarWitness.integrated_chain` совместно подтверждает принятие профиля,
связанные роли и неизменные наблюдения движения. Бездействие добавляет собственный
breachRecorded; breachRecorded для scope движения отсутствует даже в after этого
примера. Причинная гипотеза не переносит нарушение на событие машины.

## Контрпримеры и границы

| Пример                                                  | Проверенный результат                                                                 |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Ураган / AI / машина                                    | Непустые физические Added/Removed без humanAnchor                                     |
| Разные роли одной записи                                | Любые Interpretation event видят одинаковые наблюдения и diff                         |
| Другие наблюдения под тем же EventKey                   | Нельзя представить как RegisteredEvent выбранного реестра                             |
| Бездействие с ID движения и другим action/интервалом    | Raw Profile.check может принять свои основания; HumanContext этого реестра невозможен |
| Незарегистрированный ID                                 | HumanContext невозможен                                                               |
| Причина равна следствию / начинается позже              | CausalHypothesis невозможна                                                           |
| Перекрытие интервалов                                   | Допустимая причинная гипотеза в сквозном примере                                      |
| Universe без людей                                      | Общее событие представимо, HumanContext невозможен                                    |
| Unknown / конфликт / неполные основания / подмена scope | Сохранены прежние отрицательные witnesses профиля                                     |

Профили, снимок и наблюдения задаются входом. Автоматический поиск причин,
provenance физических источников, многопользовательское хранение, санкции и
parking runtime integration остаются за пределами R3.

## Проверки

Lean 4.30.0, `-DwarningAsError=true`. Event gate требует 26 named results;
attribution gate — 61 named results. Gates обходят все определения соответствующих
namespaces, включая private/generated, и допускают только `[propext, Quot.sound]`.
Нет custom axioms, sorryAx, Classical.choice или native-decide trust extension.

[Команды воспроизведения](RELATIONAL_FOUNDATIONS.md#воспроизведение) и CI
компилируют ядро и парковочные расширения, включая runtime-привязку R4. Локальные artifacts/logs
размещены на проверенном TB5. Hosted CI/review учитываются по точному SHA;
старые результаты не подтверждают новую ревизию. Demo пока использует прежний
evaluator; платные вызовы и деплой в этот срез не входят.

## Подготовка R4

Непривязанные propose/transition переименованы с явными Unbound-именами, без
compatibility aliases. Добавлены конечный EventRegistry.ofList / ofList? и
[парковочный bound entrypoint](PARKING_ATTRIBUTION.md), сохраняющий регистрацию
результата. Runtime/UI ещё не подключены к этому входу.
