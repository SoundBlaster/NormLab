# R3: актор, основание действия и переход состояния

Дата: 2026-10-25. Ledger: [#225](https://github.com/SoundBlaster/NormLab/issues/225).
Код: [ActionAttribution.lean](../lean/ActionAttribution.lean).
Общая модель: [RELATIONAL_FOUNDATIONS](RELATIONAL_FOUNDATIONS.md).

## Актор шире человека

Уточнение автора: актором может быть любая сущность, в том числе абстрактное
сообщество. Актор — **роль Entity**, а не отдельный вид человека или группы.

В выбранном R3-срезе роли разделены:

| Поле           | Смысл                                                                             |
| -------------- | --------------------------------------------------------------------------------- |
| `actor`        | Любая Entity, включая абстрактное сообщество                                      |
| `humanAnchor`  | Отдельный человек, действие/бездействие которого служит основанием этого перехода |
| `target`       | Entity, над которой совершается действие; может совпадать с actor                 |
| `instrument`   | Необязательная Entity в роли орудия                                               |
| `episode`      | Идентичность эпизода                                                              |
| `action`       | Вид действия или ожидаемого исполнения                                            |
| `start/finish` | Интервал в дискретных координатах модели                                          |

`Human` — подтип Entity по предоставленному `Universe.IsHuman`; тип actor
не имеет этого ограничения. Все literals содержат полный tuple координат.
`literal_context_injective` и `checked_scope_preserved` доказывают сохранение
контекста на уровне схемы, а не одного concrete actor/episode.

Этот модуль проверяет **переходы с человеческим основанием**. Общая онтология
допускает другие действия и события; они могут потребовать других профилей.

## Два явных профиля

`attributed(ctx)+` означает принятое в модели отнесение выбранного человеческого
вклада к actor для данного контекста. Членство человека в сообществе само по себе
этого не устанавливает. Срез требует явное основание даже для actor, совпадающего
с человеком; автоматического правила самоатрибуции пока нет.

```text
Действие:
  attributed(ctx)+, performed(ctx)+
    → actionGrounded(ctx)+
    → предложение добавить relationActive(ctx)+

Бездействие:
  attributed(ctx)+, required(ctx)+, deadlineElapsed(ctx)+,
  capable(ctx)+, exception(ctx)-, performed(ctx)-
    → omissionGrounded(ctx)+
    → предложение добавить breachRecorded(ctx)+
```

`performed` относится к выполнению выбранным humanAnchor; отрицательная поддержка
означает установленное невыполнение в том же контексте/интервале. Для бездействия
явно нужны обязанность, истечение срока, возможность исполнения и отсутствие
исключения. `deadlineElapsed` — установленное входное обстоятельство, а не
вычисление wall-clock времени по календарной фразе.

Каждая выбранная предпосылка должна иметь требуемую поддержку и не иметь
противоположной. Отсутствующая поддержка и обе полярности отклоняют определённую
атрибуцию; данные при этом не удаляются. Противоречия вне выбранных оснований
сохраняются и не блокируют переход автоматически. Противоположная поддержка
создаваемого эффекта также требует разрешения до принятия перехода.

Правило профиля должно присутствовать в `catalog`. R2b certificate строится
канонически из **всех** его предпосылок и проверяется для точного grounding
conclusion. Прямая запись candidate во facts или постороннее правило,
выводящее его без нужных оснований, не обходят checker.

## Предложение и последствие

`propose(facts, catalog, kind, ctx)` возвращает `Option GroundedTransition`.
Принятое значение содержит proof успешного `check`; свободных полей для
подменённого after-state или delta в нём нет. Методы вычисляют:

```text
before = ofList(facts)
after = before ∪ { effect(kind, ctx) }
consequence = diff(before, after)
certificate = дерево оснований выбранного профиля
```

Доказаны `checked_provenance`, точная опора certificate, `exact_added`,
`nothing_removed`, `frame`, `consequence_roundtrip` и `propose_isSome_iff`.
Добавляется только effect данного kind/context, если его ещё не было;
membership остальных literals остаётся прежним. Derived grounding candidate
не переносится автоматически в базовое состояние как часть всего Horn-замыкания.
При уже существующем effect diff может быть пустым.

`GroundedTransition.added_has_grounds` связывает каждый новый literal с effect
того же контекста, явной атрибуцией и проверенным grounding derivation.

Это переход по **правилу модели и переданным обстоятельствам**. Проверка
не устанавливает достоверность свидетельства или физическую причинность.
Многошаговые цепочки атрибуции, provenance физических источников, прекращение
отношений и назначение санкций остаются последующими профилями.

## Непустые примеры и подмены

В witness сообщество — отдельная абстрактная Entity, для которой `IsHuman` ложно;
humanAnchor — Alice. Сообщество не представлено списком людей.

| Сценарий                                                                 | Ожидаемое и доказанное поведение                 |
| ------------------------------------------------------------------------ | ------------------------------------------------ |
| Человек, атрибуция и выполненное действие                                | Принимается                                      |
| Абстрактное сообщество, Alice и явная атрибуция                          | Принимается; actor не обязан быть человеком      |
| Actor совпадает с target                                                 | Действие над собой представимо и принимается     |
| Все шесть оснований бездействия                                          | Принимается с effect `breachRecorded`            |
| Нет атрибуции сообществу                                                 | Отклоняется                                      |
| Подменён actor, anchor, target, instrument, episode, action или интервал | Отклоняется даже с правилом для подменённого ctx |
| Нет явного невыполнения                                                  | Отклоняется; unknown не становится нарушением    |
| Обе поддержки выполнения                                                 | Отклоняется; конфликт сохраняется                |
| Нет срока, возможности исполнения или отсутствия исключения              | Отклоняется                                      |
| Candidate дан как факт или выведен посторонним правилом                  | Не обходит основания профиля                     |
| Постороннее противоречие в другом контексте                              | Переход принимается; обе поддержки сохраняются   |

## Проверки и следующий шаг

Lean 4.30.0 с `-DwarningAsError=true` принимает модуль. Отдельный
[CheckActionAttribution](../lean/CheckActionAttribution.lean) требует 42 named
theorem declarations и проверяет все 358 новых declarations, включая 125 theorem
declarations и private/generated код. Allowlist — `[propext, Quot.sound]`;
`sorryAx`, `Classical.choice` и новые axioms запрещены.

Команды воспроизведения включены в [общий документ](RELATIONAL_FOUNDATIONS.md#воспроизведение)
и CI. Локальные `.olean`/логи размещены на проверенном TB5. Hosted CI/review
учитываются отдельно в PR/Issue. Локальные runtime suites, платные вызовы моделей
и деплой не выполнялись.

Следующий R4 применит аппарат к парковочному эпизоду с отдельным профильным
сопоставлением ролей, обстоятельств и результата. Demo runtime пока использует
прежний parking evaluator.
