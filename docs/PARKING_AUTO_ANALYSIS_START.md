# Начало автоматического разбора

Задача: [#200](https://github.com/SoundBlaster/NormLab/issues/200).
Дата: 23.10.2026.

## Причина затруднения

Создание черновика только сохраняло текст. Контекст изначально имел значения
«Требуется уточнение» / «Не установлен», а авторазбор требовал его ручного
подтверждения. Автоматического предложения контекста не было. Поэтому журнал
с единственной записью создания черновика соответствовал фактически выполненным
действиям: вызов модели ещё не происходил.

## Новый путь

1. Сохранить текст в черновике.
2. В разделе 02 нажать **«Предложить контекст по тексту»** — отдельный запрос к модели.
3. Проверить предложенные тему, парковочный контекст, характер обращения и объяснение.
4. Нажать **«Использовать предложение в форме ниже»**, проверить поля и дождаться сохранения.
5. Нажать **«Подтвердить контекст»**.
6. В разделе 03 нажать **«Запустить автоматический разбор»**. После предыдущей
   разметки кнопка называется «Запустить разбор заново» и требует существующего
   согласия на замену. Ручное добавление цитат расположено отдельно, после авторазбора.

Модель предлагает категорию текста. Она не устанавливает платный режим, оплату,
вид ТС или иные обстоятельства. Исходные утверждения и подтверждения сами собой
не заменяются. Ручной выбор контекста остаётся доступен при отсутствии модели.

Рядом с основной кнопкой видна конкретная причина недоступности; та же проверка
управляет disabled-состоянием. Из блока есть переход с переносом keyboard focus
к разделу 02. Черновик, открытый только для чтения, несохранённые правки,
активный разбор и юридические правки продолжают блокировать запуск.

## Реализация и журнал

- Browser → `POST /api/parking/context`: только draft ID и ожидаемая ревизия,
  действующие operator auth / Origin / CSRF guards. Контекст ещё не обязан быть подтверждён.
- App → `POST /v1/context`: существующий внутренний gateway с тем же token,
  OpenAI-совместимым Responses endpoint/model, egress и hourly quota. Клиент
  не выбирает URL, модель, prompt или schema. Одно обращение использует существующий
  bounded structured transport; автоматических повторов нет.
- Вход ограничен 8 000 UTF-16 units, source digest проверяется до dispatch/quota.
  Schema допускает только перечисленные категории и объяснение. Сохраняются
  source/prompt/config digests, фактическая модель и token usage.
- Ответ сохраняется отдельно от человеческой ревизии. Повторная проверка revision
  после await защищает новые правки; конфликт не применяет предложение.
- Приватный `context-proposal-<runId>` хранит durable running/completed/failed/conflict
  receipt и предложение. После перезапуска незавершённый запрос показывается как
  interrupted с неизвестным исходом. GET сохранённого предложения не вызывает модель.
- Журнал показывает запрос контекста, выполнение, результат, конфликт или ошибку.
  Пока запрос выполняется, журнал обновляется автоматически.
  Ошибки доступа/баланса/сети сохраняют безопасную диагностику с этапом `context`.
  После timeout запрос мог быть оплачен; ручной выбор доступен, повтор — явный.

Существующий discovery/classification pipeline и его profile digest не меняются.
Новый контекстный prompt имеет собственную identity. Для VPS требуется обновить
приложение и gateway одним образом; новых ключей и внешних сетевых назначений нет.

## Выполненная проверка

- TypeScript, Oxlint, FSD, форматирование, schema freshness и production build.
- Локальный UI с синтетическими черновиками, 390 × 844: неподтверждённый контекст
  → предложение через заглушку → перенос в форму → автосохранение → явное подтверждение
  → доступная кнопка первого авторазбора.
- Переход к контексту действительно перенёс focus. Ширина документа 390 px,
  блока авторазбора — 320 px. Журнал содержит start/completed контекстного запроса;
  extraction-start отсутствует, поскольку кнопку запуска извлечения не нажимали.
- Ровно 15 browser-вызовов, два screenshot, оба открыты и визуально просмотрены.
  Счётчики локального сервера: один вызов заглушки контекста, ноль вызовов извлечения.
  Повторный запуск с заменой, error/restart paths, console и live API в браузерный
  scope не вошли. Проверена механика интерфейса с заглушкой, не качество модели.
- [Предложение контекста](evidence/parking-context-proposal-mobile-2026-10-23.png),
  [готовность к авторазбору](evidence/parking-auto-ready-mobile-2026-10-23.png).
- Автоматические тесты не добавлялись и локально не запускались. Платных запросов,
  изменений production, merge и deployment в этой задаче не было. Новая контекстная
  классификация у реального провайдера остаётся непроверенной до отдельного smoke.
