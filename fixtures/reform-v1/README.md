# Reform fixture v0.1.0

Конкретизация NL-107 для [демонстратора A/B/C](../../docs/DEMONSTRATOR.md). Статус: **specified; arithmetic-audited; producer-tested; Lean-decision/comparison-verified; core/CLI-explanations-and-metrics; not-HTTP-integrated**.

- [source.md](source.md) — полный синтетический исходный текст A/B/C с устойчивыми ID положений.
- [fixture.json](fixture.json) — машиночитаемый design artifact: domain, положения, source mappings, ожидаемые значения и queries.
- [VALIDATION.md](VALIDATION.md) — результаты ограниченной проверки fixture и оставшиеся обязательства.
- [check_fixture.py](check_fixture.py) — воспроизводимая проверка полноты таблицы, арифметики, mappings и заявленных отношений на конечной области.
- [metric-annotations.json](metric-annotations.json) — reviewed source definitions и нормативные отсылки с точными model/source bindings для NL-108.

Формат `normlab.reform-fixture-plan/v1` предназначен для этого source fixture. [server/reform-models.ts](../../server/reform-models.ts) собирает из него typed NormPackages/NormBundles нового [контракта v2](../../docs/CONTRACTS.md). Сам fixture plan сохраняет отдельный формат и не является входом существующего Lean verifier M0.

## Что меняется

| Переход               | Изменение                                                  | Ожидание                                                     |
| --------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| A → B                 | Две пары одинаковых правил M/N заменяются общими правилами | Все типизированные последствия сохраняются                   |
| A → C                 | Множитель M меняется с `2/3` на `1/2`                      | При M срок строго уменьшается; вне M последствия сохраняются |
| C → ошибочный вариант | Теряется исключение E для правила N                        | Возникает изменение вне заявленной категории M               |

В A семь нормативных положений, в B и C — по пять. Здесь единица подсчёта — отдельный именованный нормативный section в source.md; определения и заголовки моделей не включаются. Независимых обстоятельств M/N/E остаётся три. [Методика NL-108](../../docs/METRICS.md) реализует separate structure/decision/change counts, reviewed source annotations и CLI replay. Group-expanded rules остаются восемью во всех трёх моделях.

## Domain и последствия

`D = {K1, K2} × {false, true}³`, порядок обстоятельств: M, N, E. Все 16 завершённых комбинаций включены; дополнительных скрытых ограничений нет. `false` соответствует `refuted`, `true` — `established`.

Mapping входов и последствий между A/B/C — identity. Сравниваются квалификация группы, срок, штраф и валюта. Source IDs, derivation и ledger различаются между моделями и не являются компонентами equality нормативных последствий. Эквивалентность не требует одинакового digest представления.

## Незавершённые установления

Для будущего semantic profile предлагается сохранить четыре состояния каждого finding. `unreviewed` и `not-established` дают обе completion-возможности; они не преобразуются в `refuted`.

В пределах этого fixture статус `complete` требует terminal findings всех трёх обстоятельств. Иные snapshots остаются `conditional`. Совпадение численных последствий разных completions не удаляет сами условия ветвей. Этот простой критерий явно выбран для первого фрагмента; более общая процедурная завершённость относится к NL-102.

Пример: K1, M установлено, N открыто, E опровергнуто. A/B имеют ветви 80 и 60 месяцев; C — 60 и 45. В каждой ветви штраф 200 000 DEMO. Сводный ledger отмечает N как `unresolved`; branch ledger показывает фактическое применение для каждого completion.

Пример исключения: K1, M и N установлены, E установлено. B: 80 месяцев, B-M `applied`, B-N `excluded` с основанием B-X, B-X `applied`. C: 60 месяцев с аналогичным ledger. Исключение N не отменяет M.

## Заявленные queries

1. **Q-AB-equivalence:** A и B имеют одинаковые полные последствия для каждого x из D.
2. **Q-AC-no-increase:** срок C не превышает срок A; штраф, валюта и квалификация сохраняются для каждого x из D.
3. **Q-AC-strict-M:** при M срок C строго меньше срока A — восемь случаев.
4. **Q-AC-outside-M:** при опровергнутом M последствия C равны A — восемь случаев.
5. **Q-M-monotonicity:** для каждой модели при неизменных группе/N/E установление M строго уменьшает срок и сохраняет остальные последствия — восемь пар на модель.

Существование/единственность относительно независимого отношения допустимости и soundness/completeness decision results подтверждены в [NL-106](../../docs/REFORM_VERIFICATION.md). Таблица используется как независимый producer regression oracle. [NL-405](../../docs/COMPARISON_VERIFICATION.md) подтверждает все перечисленные queries через Lean и выпускает signed receipts с export/replay. Отдельный [поддержанный erroneous amendment](../reform-counterexample/README.md) даёт verified counterexample; исходный design variant без exclusion сохраняется и отклоняется admission validation текущего profile.

## Воспроизведение аудита

Из корня проекта:

```sh
python3 fixtures/reform-v1/check_fixture.py
```

Checker поддерживает только данный design format и конечную область. Он не выдаёт `verified` приложения, не использует его interpreter и не заменяет Lean kernel verification.
